# The Meme Generator Factory (Factory Method)

Иерархия `MemeCreator` выпускает мемы в разных форматах и **реально проверяет раскладку**:
слишком длинный текст переносится по словам, шрифт уменьшается, а если не помогло, текст отклоняется.
Выйти за границы холста невозможно.

## Запуск (нужен JDK 17+)

```bash
./run.sh          # демонстрация
./run.sh test     # 14 тестов без внешних библиотек
```

## Структура

```
src/memes/
  Meme.java                  продукт (интерфейс)
  MemeCreator.java           абстрактный создатель: create() = шаблонный метод, build() = фабричный
  TextFitter.java            общая валидация: перенос + подбор шрифта + отклонение
  FitPolicy.java             SHRINK (ужимать) / REJECT (только отклонять)
  FittedText.java            результат подгонки (строки + размер шрифта)
  LayoutException.java       отклонённый текст
  TopBottomMeme(+Creator)    формат 1 (SHRINK, шрифт 48..20)
  CaptionMeme(+Creator)      формат 2 (REJECT, шрифт 32)
  Main.java                  демонстрация
  comic/ComicPanelMeme(+Creator)   формат 3 для ЖИВОЙ ЗАЩИТЫ (отдельный пакет)
test/MemeTests.java          тесты
```

## Аналогия

Сеть типографий. У каждой (создатель) свой формат бумаги, и она сама проверяет, влезет ли текст:
сначала переносит строки, потом уменьшает шрифт, а если не помогло, отказывает в заказе.
Новый тип открытки означает новую типографию рядом, старые не разбирают.

## Как это работает

- `MemeCreator.create(...)` объявлен `final`: проверяет количество и пустоту текстов, затем вызывает `build(...)`.
- `build(...)` (фабричный метод) переопределяет каждый формат. Внутри он вызывает `fit(...)`, то есть общий `TextFitter`.
- `TextFitter`: ширина символа = 0.6 * шрифт, высота строки = 1.2 * шрифт. Для каждого шрифта от max к min
  текст переносится по словам. Если нет слова шире строки и `строк * шрифт * 1.2 <= высота`, подгонка успешна.
  Иначе после минимума бросается `LayoutException`.
- Политика `REJECT` пробует только максимальный шрифт, то есть ужатия нет.

## План живой защиты (3-й формат)

Формат уже лежит в `comic/`, а в `Main` он подключается одной строкой `register(creators, new ComicPanelMemeCreator())`.
Чтобы показать «с нуля», удалите пакет `comic` и напишите два класса:

1. `ComicPanelMeme implements Meme` (запись из списка `FittedText`).
2. `ComicPanelMemeCreator extends MemeCreator`: `name()`, `expectedTextCount() = 3`,
   `build(...)` вызывает `fit(...)` с областью `CANVAS_WIDTH / 3` x `150`.

Ни `MemeCreator`, ни `TextFitter`, ни `TopBottom*`, ни `Caption*` не меняются. Это Open/Closed.

## Big O

k = число текстов, L = длина текста, F = maxFont - minFont (константа).

| | Время | Память |
|---|---|---|
| Best | O(L): первый же шрифт подошёл (одна обёртка текста), либо мгновенный отказ на пустом вводе за O(1) | O(L) |
| Average | O(k * F * L): для каждого шрифта делается перенос, пропорциональный длине | O(L) |
| Worst | O(k * F * L): перебор всех шрифтов до минимума и затем исключение | O(L) |

`create` отсекает ввод длиннее 500 символов, поэтому L ограничено и на практике всё работает за O(k).
Память: список строк для одной подгонки, O(L); итоговый мем хранит O(k * L).

## Вопросы для самопроверки (с ответами)

1. **Зачем `create` объявлен `final`?** Чтобы наследник не мог обойти общую проверку входа. Подкласс меняет только `build`.
2. **Где здесь Factory Method?** `build(...)` в `MemeCreator` (абстрактный) и его реализации в подклассах. Клиент вызывает `create` и не знает конкретный формат.
3. **Что нарушало бы Open/Closed?** Один создатель с `switch` по названию формата: каждый новый формат требовал бы правки этого класса.
4. **Как для одного формата сделать «только отклонять»?** Передать `FitPolicy.REJECT`, как в `CaptionMemeCreator`. Остальные не затрагиваются.
5. **Чем отличается от Abstract Factory?** Здесь один продукт на создателя, выбираемый переопределением метода. Abstract Factory создаёт семейства связанных продуктов.
6. **Почему длинное слово без пробелов отклоняется, а не режется?** Режем только по пробелам. Слово, которое физически не влезает в строку на минимальном шрифте, означает невозможную раскладку, поэтому честнее отказать, чем переполнить холст.
7. **Какие граничные случаи покрывают тесты?** Пустой и `null` текст, неверное количество, ровно 33 символа (проходит) и 34 (отклоняется) на шрифте 20, длинное слово в узкой панели, REJECT без сжатия.
